# 首次使用与采集权限

OneShot 在开始新采集前需要两项独立权限：

| 权限 | 用途 |
| --- | --- |
| 屏幕录制 | 截取用户选定的应用窗口，保存为标注用的截图；不会在后台持续录屏 |
| 辅助功能 | 读取控件、文字与状态，将标注绑定到对应界面元素 |

## 首次启动

发布版首次启动显示“开始使用 OneShot”引导，并被动检查当前权限。打开引导不会自动申请系统授权或开始截图。

1. 点击“开启屏幕录制”，在系统提示中选择操作。
2. 点击“开启辅助功能”，在系统提示或设置中选择操作。
3. 从系统设置返回 OneShot 后，应用会重新检查两项状态；也可点击“重新检查”。
4. 两项都确认开启后，点击“开始使用 OneShot”。切到目标应用再按 ⌃⌥⌘S，或使用 3 秒倒计时。

每项请求单独执行。若系统提示仍在等待处理，先完成它，再请求下一项。请求按钮点击成功不代表权限已经授予；状态以新的采集进程重新检查的结果为准。

## 没有出现系统提示

曾经拒绝过请求、应用更新后的签名变化，或系统的权限状态都可能影响再次提示。引导中的每一项均提供“前往系统设置”，并显示手动路径：

- 系统设置 → 隐私与安全性 → 屏幕录制（部分版本显示为“屏幕与系统音频录制”）。
- 系统设置 → 隐私与安全性 → 辅助功能。

找到 OneShot 或 OneShot Capture，以系统实际显示名称为准。采集组件内置在 OneShot.app 中。设置跳转是便利入口，不保证所有 macOS 版本都会自动定位到准确面板，因此保留手动路径。

开启后返回应用再检查。如果系统要求退出重开，先退出 OneShot，再从安装位置重新打开。当前预发布使用 ad-hoc 签名，替换应用后可能需要重新确认权限。OneShot 不自动重置权限数据库、批准权限或关闭系统安全保护。

## 暂时只编辑已有材料

点击“稍后设置”可以继续打开、标注和导出已有项目，不需要为离线编辑授予采集权限。再次开始新采集时会回到权限引导；也可从菜单或采集设置中的“权限与首次使用…”随时打开。

引导完成记录不会替代实际权限。后续启动或从设置返回时，如果权限已失效，应用重新显示缺失项。无法检查时显示“待确认”，不把未知状态当成已授权。

## 开发与验证

发布采集组件在标准 AppKit 启动完成后处理显式请求：

```sh
oneshot authorize --permission screen-recording --output /absolute/path/to/new-report
oneshot authorize --permission accessibility --output /absolute/path/to/another-report
```

这些是内部采集组件的 CLI 示例，不需要普通用户从终端运行。`doctor` 只检查、不请求；旧的无参数 `authorize` 仍兼容，先屏幕录制、后辅助功能。GUI 使用独立按钮，避免把两项系统交互挤在一起。

请求记录区分 AppKit 启动、实际请求类型、调用前状态、API 是否调用及 API 返回值。完成回执仅证明请求进程结束；应用会启动新的 helper 再检查授权，避免沿用旧进程中的缓存。请求返回后不再仅为等待辅助功能而保活五分钟。

自动测试覆盖单项请求计划、未知／部分／全部授权状态、稍后设置、权限失效后的重新引导和检查错误后的状态清理。原生 UI 验收不自动点击系统的批准按钮；实际提示、用户批准和之后的真实采集仍须在安装后的同一应用路径验证。
