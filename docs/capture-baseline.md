## 逐应用验收

| 样本 | 已观察到的基准 | 尚未由此证明 |
| --- | --- | --- |
| 音乐 | 原生窗口；侧栏/专辑/音轨关系；role、description、value、details、部分 ID；数值类型、可设置状态；选中/展开；音量；焦点 | 搜索词读取、播放进度、完整资料库、所有播放状态、稳定全局元素 ID |
| OpenSurge | `wails://localhost/policies`；HTML 节点的大段富文本；策略组与节点、协议/UDP、延迟、检测时间、出口/选择标记；明显超过截图视口的内容；滚动值 | 完整 DOM、每个按钮均为独立 AX 节点、未加载内容、原生具体提取 API |
| Cursor | 文件 URL 与工作台内部 URL；文件树/编辑器组/标签/设置/聊天的层级；长编辑器正文与视口外内容；焦点与控件选择 | 精确文本选区、所有标签对应文件全文、完整聊天、AX 不可用回退、OCR |

Cursor 是本次 AX 成功的正向样本。编辑器正文在句中结束，截断阶段与上限未知。`selected` 行/标签、焦点与文本选择必须分开。OpenSurge 与 Cursor 的焦点段会重复正文，重复内容不增加覆盖率。

## 核心要求

1. 捕获明确指定的同一窗口。CG 窗口 ID/PID 与 AX 标题/几何匹配独立记录，歧义拒绝，不静默选择另一个窗口。
2. 遍历应用暴露的上下文，不按可见区域、几何尺寸或“可操作控件”剪枝。表格/列表不能仅用可见行代替完整子关系。
3. 普通属性与长正文都保留。按实际声明探测参数化富文本；来源保留为原始 AX 属性名。AX、富文本、OCR 分开保存。
4. 长度/节点/深度/超时及读取失败有明确状态。自身未触发限制，也只能表述为完成所请求的读取，应用是否暴露全文仍未知。
5. 原图与结构化上下文可离线重读；没有标注也有完整产物。焦点引用已有节点，不能制造错误父子关系。
6. 截图和 AX 有各自时间。窗口身份检查不能证明内容原子一致；跨读变化必须反映到诊断。

## 当前实验方案

独立 Swift 原型，macOS 14+，无第三方运行时依赖：CoreGraphics 识别窗口；ScreenCaptureKit 捕获原图；ApplicationServices 读取 AX；Vision 仅对冻结图片做可选中英文 OCR。不复制参考项目或 Codex 专有代码。

结构化输出 `accessibility.json` 保存角色、属性类型、值、关系、焦点和诊断；`context.txt` 是完整可读导出；`manifest.json` 保存每个阶段成功/失败与窗口一致性；`screenshot.json`、`ocr.json` 记录各自来源和时间。新捕获创建新目录，拒绝覆盖。

运行 `python3 scripts/summarize_capture.py <捕获目录>` 得到节点/角色、长正文、URL、富文本来源、焦点和诊断清单。这些是检查线索，不是自动生成的“完整度百分比”。

正式验收还需逐项人工核查控件关系、视口外内容、状态语义和正文范围。精确选区、权限拒绝、目标窗口变化与长文本预算分别作为补充实验。
