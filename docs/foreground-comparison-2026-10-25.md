# 前台窗口采集与 AppShot 对照：2026-10-25

## 范围与对照来源

本轮按用户确认的范围，只验收已打开、前台可见的目标窗口。后台窗口支持和编辑器全文扩展后置。用户手动将音乐、OpenSurge、Cursor 依次置前；OneShot 不更改页面、滚动、播放、网络策略、文档或屏幕阅读器设置。

原生 AppShot 对照来自用户在对话中提供的历史样本：音乐 04:33:32Z、OpenSurge 04:33:39Z，以及 Cursor 05:51:23Z。新 OneShot 样本保存实际时间、前台应用/PID、CG 窗口身份和各组件结果。它们不是同一时刻采样；只有内容仍一致的静态场景可逐项对应，滚动、相对时间、文档或聊天变化单列，不能算漏采。

本轮普通 CUA 工具读取音乐两次超时（30/60 秒）、OpenSurge 一次超时（30 秒），没有取得新 CUA 参考。CUA 同时明确禁止操作 Codex 自身界面；文字会话不能调用语音专用捕获工具。因此没有自动创建新的原生 AppShot，也没有把普通截图或 OneShot 结果标作 Codex AppShot。严格的同一轮原生 AppShot 对照仍需用户从正常入口提供。

## 音乐：静态专辑场景覆盖

新截图与用户原 AppShot 显示同一专辑、音轨、最近添加侧栏及专辑标题焦点框；窗口在屏幕中的位置改变，内容布局和尺寸保持一致。逐项核对以下内容已保留：

- 专辑标题、艺人、分类/年份、音轨名称、时长、iCloud 下载与已喜爱状态。
- 最近添加侧栏的选中行和单元格、播放列表层级、播放和随机播放等控件。
- 音量数值及数值类型、两处评级与“没有星”、无损说明。
- `AXFocusedUIElement` 指向专辑标题 `n71`，与原 AppShot 焦点说明和截图焦点框相符。

119 节点与前次本机完整样本比较，除几何属性外，其他属性一致。没有触发节点、深度、超时或文本预算截断。仍有 27 项 `AXError.failure`：GrowArea 1、Identifier 7、MakeScreenRectVisible 2、ScrollToVisible 16、ValueDescription 1；保留 `partial_read_errors`，不把它们删掉后宣称完整。

发现的结构缺口是 `AXSelectedRows` / `AXSelectedCells` 引用没有解析为已采集节点。实际行/单元格的 `AXSelected=true` 已保存，但旧 JSON 未保留可用于核验对象身份的句柄，不能仅凭相同内容认定引用对象完全一致。多个节点自报 `AXFocused=true`，唯一焦点判断以应用的 `AXFocusedUIElement` 引用为准。

封面和视觉焦点框由截图保留；封面缺少有意义的 AX 图像描述。OCR 可读主要可见文字，但部分图标、星级、版权符号有误读，不能替代 AX 的状态和值。离线摘要还确认一个 `AXSections` 嵌套对象和 30 次字体／前景色运行属性以未支持占位保存，尚未无损序列化。

## OpenSurge：同策略页的跨视口覆盖

新截图显示 Steam 社区组末尾和 SupaBoard 组开头；历史截图显示 SupaBoard 整组。检测相对时间也已从几十分钟前变成几小时前。这两项属于场景状态变化，不能作像素或逐字一致断言。

已核对 `wails://localhost/policies`、13 个策略组标题、229 个 AXCheckBox（226 个出口选项和 3 个筛选开关）。14 个复选框值为 1，分别对应每组当前选择及全局策略筛选。名称、协议、UDP、延迟、当前出口与页面检测范围说明均可从结构化属性或富文本中取得；页面标题、其他策略组和底部说明超出当前截图视口，仍在 AX 中。

原始错误仍保留：根窗口 `AXGrowArea` 读取失败；`AXLinkedUIElements` 有未解析引用；应用返回的焦点属于目标窗口之外，记录为 `outside_target_window`，没有用另一个窗口的正文代替。本轮不能宣称已验证与原 AppShot 相同的 HTML 焦点。

复选框选中状态来自 `AXValue=1`，不能用其均为 false 的 `AXSelected` 替代。自动选择与故障转移组的 30 个出口选项保留不可用状态。富文本中的字体、颜色和附件对象仍是明确的未支持占位；窗口 `AXSections` 的两个嵌套字典也未序列化。它们不等于正文截断，但不允许宣称所有属性无损。OCR 有字形误读和多列顺序问题，精确控件状态优先使用 AX。

## Cursor：编辑器不可访问，聊天仍可采集

窗口文件 URL、工作台内部 URL、文件树选中项、文档标签选中项与右侧聊天标签都已保留。它们指向用户指定的 Team Cross 文档及聊天，与 05:51:23Z 的 AppShot 锚点相符。

编辑器节点 `n563` 明确报告“现在无法访问编辑器。 若要启用屏幕阅读器优化模式，请使用 Shift+Option+F1”，`AXValue` 为空且 `AXNumberOfCharacters=0`。这与用户 AppShot 的空编辑器相符。本轮没有启用屏幕阅读器模式、滚动拼接或额外读取文件；当前可见编辑器文字由截图保留，OCR 单独提取，不伪装为 AX 正文。

右侧聊天的核心方向、五条流程及后续推进段落均已取得。流程 4、5 在本轮截图之外，但存在于富文本和独立的标题、列表节点中；部分节点高度为 0，遍历没有因此过滤。这里验证的是应用已经暴露的屏幕外文本，不是完整聊天历史。

本轮截图为 3024×1888，历史 AppShot 为 3736×2110，编辑器列宽、滚动位置及聊天视口有所变化。本轮焦点是 WebArea `n14`，历史 AppShot 焦点为空编辑器；这些是两次状态差异。只有一项 `AXGrowArea` 读取错误，未触发节点、深度、文本或时间预算截断；仍有 `AXSections` 的嵌套字典和富文本字体对象未序列化，不能把空诊断列表理解为全部属性完整。

## 本轮修正与验证

- 新增只读前台门槛脚本 `capture_frontmost.py` 和 `frontmost-state.swift`：先确认前台应用、PID、窗口可见性，再捕获一次，并保存前后状态、完成回执和二进制摘要。首次条件不满足的拒绝和后续 Cursor 成功均有实机证据。脚本离线覆盖非前台、不可见窗口、捕获后前台变化、完成未知及重复输出目录；完成未知时停止，不自动重发。
- 修复 `AXSelectedRows` / `AXSelectedCells` 的引用处理：等待窗口树遍历完成后，按 AX 对象身份绑定已采集节点；未知对象或未读节点保持未解析，不扩大采集范围。
- 补齐离线摘要：分别统计属性状态、嵌套未支持值、富文本运行属性占位、部分解析状态与未解析引用。原始 JSON 中的重复记录分别计数，不作为独立内容总量；扫描预算耗尽时明确标记下限，不把 `no_value` 或不透明句柄混为普通读取错误。
- `zsh scripts/test.sh` 的 20 项 Swift 测试通过，包括“先读到选中引用、后读到行/单元格”的回归用例。修复只进入源码和测试，没有替换本轮固定 App，因此尚不能据此宣称音乐的实机引用缺口已消除。
- `python3 scripts/test_summarize_capture.py` 的 2 项离线回归测试通过；三份冻结样本重复统计一致，原有 22 个摘要字段保持兼容。新统计均未触及扫描预算。未解析引用值可能包含主动不遍历的窗口外关系，不等于丢失相同数量的正文或独立对象。

## 当前判定

三款应用均完成一轮符合前台前提的真实采集。音乐的主要静态语义锚点、控件状态和焦点已与历史 AppShot 对应；OpenSurge 的同一策略页主要语义及视口外覆盖已验证；Cursor 保留窗口结构、空编辑器状态和大量聊天内容，与后续 AppShot 的可访问性边界相符。滚动、布局和焦点差异单独记录。全部结论均不代表所有属性或完整文档，也不以节点数或重复富文本字数生成完整率百分比。

后续只补齐前台场景内缺项，以及同一轮原生 AppShot 样本；不因后台窗口不可用或编辑器未暴露全文扩展本阶段范围。原图、原始 AX/OCR、前台记录与详细审计留在 Git 忽略的本机目录，Git 仅收录方法、代码和不包含私人内容的结论。
